# Phase 5.11 release and integration gates adversarial assessment

## Scope and method

This separate offline assessment reviewed the Phase 5.11 execution prompt,
governing packaging and module contracts, machine-readable gate ordering,
release inventory, compatibility decisions, and deterministic validator. It
attempted to falsify candidate/release separation, prerequisite completeness,
evidence freshness, public-download identity, manifest truthfulness, claim
ceilings, cross-repository pinning, release ordering, and authorization scope.
No target, public release, or consuming repository was accessed or changed.

## Findings and reinjection

1. **Pre-upload checksum ambiguity:** a locally verified checksum could have
   been mistaken for public-artifact verification. The contract now requires a
   fresh download location, a distinct extraction path, outer SHA-256, every
   inner checksum, provenance, and install-input verification.
2. **Tag-to-bytes ambiguity:** a matching version-shaped tag did not alone bind
   the source and generated bytes. The candidate freeze and tag gate now bind
   the exact commit, archive, UAPI, overlays, manifest, metadata, and notes.
3. **Populated-manifest overclaim:** nonempty entries did not necessarily make
   their states truthful. The manifest gate now requires exact evidence for
   every non-default state, route, mode, and live flag and enforces claim
   ceilings.
4. **Upload-versus-confirmed publication:** an upload or draft release could
   have unlocked integration. The ordered contract places public-download
   verification after publication and before all consumer work.
5. **Header-only integration:** byte equality alone could miss semantic drift,
   while semantic checks alone could tolerate different canonical bytes. The
   adapter gate requires both plus exact module archive, manifest, and adapter
   pins before WsprryPi integration.

The findings were added to the prompt, governing contract, machine-readable
gate contract, and validator. Affected checks and the full offline suite were
repeated.

## Final assessment

No remaining objective finding was identified within Phase 5.11's offline
scope. The current `0.0.0-phase5.2` identity remains a non-published candidate:
the representative lifecycle matrix, Gate F publication, public-download
verification, and dependent integration/release gates remain open. This review
provides no target, lifecycle, hardware, GPIO, timing, RF, publication, or
cross-repository integration evidence.
