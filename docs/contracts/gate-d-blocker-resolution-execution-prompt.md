# Gate D blocker-resolution execution prompt

## Mission and boundary

Resolve Gate D inputs offline without contacting or mutating `wspr4`, `wspr5`,
or `wspr5-rescue`. Freeze a genuine predecessor/successor pair and a bounded
output-disabled busy-state injector. Prepare exact representative-build and
target-authorization dossiers. Keep genuinely unavailable kernel, signing,
header, and foreign-conflict identities blocked; do not weaken the matrix to
make `--require-ready` pass.

No package, DKMS, signing, key, module, overlay, service, boot, reboot, GPIO,
clock, DMA, transmitter, Si5351, SDR, antenna, RF, tag, publication, download,
or consuming-repository action is authorized.

## Exit gate

The slice closes when the version pair and injector are machine-validated, the
successor is reproducibly sealed, every row has an exact truthful disposition,
the full offline suite passes twice at the successor commit, and adversarial
review has no unresolved offline finding. Gate D execution remains blocked if
any required external identity is absent.

## Reinjected findings

1. Adding blocker-resolution tooling changes candidate inputs. Preserve frozen
   `0.0.0-phase5.2` as the predecessor and use distinct successor
   `0.0.0-phase5.13`; never rebuild changed bytes under the predecessor name.
2. The busy-state injector must emit and flush a readiness record while the
   descriptor or lease is still held. A result printed only after cleanup
   cannot coordinate a removal-refusal attempt.
3. The injector is separate test evidence, not an installed operator feature.
   Exclude its source, test, concrete version pair, and execution instance from
   the candidate archive and package inventory.
4. Historical Phase 4 build evidence names different module bytes and cannot
   create a positive successor decision. Prepare a Gate C request and retain
   `manifest-has-no-exact-positive-entry` until exact successor build evidence
   is accepted.
5. A fake kernel string, non-enforcing signature simulation, removed known-good
   headers, or manufactured foreign owner does not satisfy a representative
   row. Keep those rows blocked unless a genuinely matching identity is
   supplied or a separately justified policy revision preserves the original
   assertion.
6. The absent positive manifest decision transitively blocks every row that
   must reach installation or output-disabled load, not only the nominal
   current-kernel row. Record that dependency on each affected row.
7. A byte-complete predecessor package is not a target-proven rollback. Name
   the field `packageComplete`, retain the target rows as unexecuted, and never
   use offline package validation as lifecycle evidence.

Repeat adversarial review, reinject every objective finding here and in the
implementation, invalidate affected evidence, and rerun affected checks.
