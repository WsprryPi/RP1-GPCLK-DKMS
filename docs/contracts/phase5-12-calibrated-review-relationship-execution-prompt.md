# Phase 5.12 calibrated-review relationship execution prompt

## Authority, mission, and exit condition

Execute only the bounded offline Phase 5.12 portion of
`phase5-packaging-operator-enablement-execution-prompt.md`. Contract, release-
policy, machine-readable metadata, deterministic tests, and documentation
changes are authorized. This slice does not authorize target access or
mutation, package or DKMS administration, signing or key changes, module or
overlay administration, boot changes, reboot, GPIO, clock, DMA, transmission,
SDR or calibrated measurement, RF, tagging, release publication, public-
artifact download, issue changes, or consuming-repository changes.

Phase 5.12 closes when the Experimental-prerelease and final-review boundaries
are explicit in the governing contract and a packaged policy artifact;
packaging cannot create `Qualified`; calibrated review is bound to one frozen
packaged candidate; change invalidation and affected-lifecycle reruns are
machine-checked; the full offline suite passes twice; and a separate
adversarial assessment has no finding. No external evidence gate closes here.

## Required release policy

1. Phase 5 packaging may produce an Experimental prerelease from the existing
   receiver-relative evidence only after all applicable packaging, lifecycle,
   integrity, and adversarial gates pass. Publication still requires explicit
   Gate F authority.
2. The prerelease identifies its exact receiver-relative scope, residual risk,
   limitations, `Experimental` state, and non-final status. It never claims
   calibrated frequency, power, spectrum, or final `Qualified` status.
3. No identity becomes or remains final `Qualified` merely because packaging,
   DKMS, signing, installation, representative lifecycle, reproducibility, or
   publication succeeds.
4. Calibrated qualification uses the exact frozen packaged candidate, bound by
   source commit, archive SHA-256, UAPI identity, overlay hashes, manifest
   hash, package/tool identities, and expected tag.
5. Calibrated results enter a newly reviewed final manifest and release
   decision. `Qualified` applies only to exact route/mode and system identities
   with every required evidence class complete; incomplete or failed rows keep
   the truthful lesser state.
6. An Experimental prerelease is immutable. Calibrated results do not relabel
   it in place; the final release has a separately reviewed identity.
7. If calibrated testing changes module behavior/source, overlays, UAPI,
   timing, packaging/generated bytes, signing, compatibility policy, or
   lifecycle tooling, assign a new candidate identity, invalidate every
   affected Phase 5 result, rerun affected lifecycle and release checks, and
   review the revised final manifest.

## Offline implementation and validation

Record this policy in
`release/calibrated-review-release-policy-v1.json`, include it in the release
inventory and archive validation, and reject packaging-to-Qualified promotion;
final Qualified release before calibrated review; review against a different
or incompletely frozen candidate; in-place prerelease relabeling; final release
without a newly reviewed manifest; incomplete route/mode rows; and relevant
changes without invalidation and affected Phase 5 lifecycle reruns.

Run SPDX, whitespace, documentation-link, release-unit, and complete offline
checks twice from clean generated-output locations. Independently attempt to
falsify authorization separation, prerelease truthfulness, claim ceilings,
candidate identity, manifest review, immutability, route/mode independence,
invalidation coverage, and rerun requirements. Reinject every objective
finding into the prompt, contract, policy, decision, or tests and repeat until
none remain.

### Reinjected findings

1. Receiver-relative evidence is not a shortcut around applicable lifecycle,
   integrity, review, enrollment, or Gate F prerequisites.
2. Bind “frozen candidate” to commit, archive, UAPI, both overlays, manifest,
   package/tool identities, and expected tag.
3. Require a newly reviewed final manifest and separately immutable release;
   never relabel an Experimental prerelease in place.
4. Cover behavior/source, overlays, UAPI, timing, package/generated bytes,
   signing, compatibility, and lifecycle tooling in change invalidation.
5. Keep GPIO4/GPIO20 and QRSS/TONE, FSKCW, DFCW, and WSPR independent; retain a
   lesser state for every incomplete or failed row.

## Completion report

Report changed files, exact checks and skips, policy classification, all
target/system/hardware/RF/publication actions not performed, documentation and
qualification impact, final Git state, and the next separately authorized
gate. Do not report publication, calibrated review, final-manifest approval,
`Qualified`, or Phase 5 completion without their external evidence.
