# RP1-GPCLK-DKMS 1.0.1 planned behavior

Version `1.0.1` is an unreleased corrective candidate. It preserves the v1
UAPI, `/dev/rp1-gpclk`, both route overlays, and the stock RP1 resource model.

The endpoint and normative UAPI contract are frozen for consumer development:
ABI 1, canonical header SHA-256
`1d411644352e61402bd4685a5692070d543ab2ee5b016d394294aa98970bd7fb`,
source/DKMS/module version `1.0.1`, Debian version `1.0.1-1`, and eventual tag
`v1.0.1`. GPIO4 is route 1 and GPIO20 is route 2; their compatibility evidence
is independent. Any endpoint or UAPI change reopens this freeze and invalidates
consumer work. This is not the final documentation freeze: target evidence and
the final compatibility entry remain pending.

The module now requires exactly one enabled endpoint node. It reuses a
kernel-created platform device when present. If the firmware-applied boot
overlay left that exact RP1 child uninstantiated, the module finds the nearest
instantiated platform ancestor and creates the child with that Linux device
parent using exported OF APIs. This accommodates the stock Pi 5 topology where
the intermediate `rp1` firmware node has no platform device. It requires
synchronous binding, records ownership,
and unregisters only that owned device during teardown. It rejects
missing, duplicate, disabled, ambiguous, or unbound endpoints.

This correction has hardware-free evidence only until a separately authorized
output-disabled target run verifies the boot-time platform device, binding,
probe result, canonical character device, and cleanup for each route. It makes
no live-output, timing, transmission, RF, or broader compatibility claim.
