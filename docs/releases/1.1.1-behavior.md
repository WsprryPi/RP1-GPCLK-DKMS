# Release 1.1.1 behavior

Release 1.1.1 recycles the ABI v2 candidate without changing the canonical
UAPI. It adds an exact, route-specific, reboot-based target-validation plan and
a read-only post-boot inspector for GPIO4 and GPIO20. The package installs both
overlays inactive and never selects a route.

The package also installs the stable `rp1-gpclk-route-manager-v1` consumer
contract at `/usr/sbin/rp1-gpclk-route-manager`. Its operations are `query`,
`preflight`, `apply-and-reboot`, `rollback`, and `reconcile`; it is independent
of the qualification archive executor described below. Installation remains
inactive and creates no boot selection or transaction journal.

The revised application protocol permits preflight while WsprryPi is active.
Mutation uses a disabled-by-default, group-restricted systemd socket; the root
per-connection service journals, stops, and verifies only the two fixed
services before a boot write. WsprryPi retains scheduling and execution-idle
policy. The executor-bearing package is a new artifact and is explicitly
output-inhibited-unvalidated pending exact-package target evidence.

Completed journals from the earlier 1.1.1 qualification executor remain
byte-exact in the transaction directory and are reported as historical after
strict terminal validation. The earlier package-owned route-block metadata is
accepted as historical and upgraded only by the next journaled route change.
Nonterminal, altered, or unknown retained state continues to fail closed.

Both routes remain `Unavailable` and `liveEligible: false` in the hardware-free
candidate. GPIO4 evidence cannot qualify GPIO20, GPIO20 evidence cannot qualify
GPIO4, and neither route inherits evidence from 1.1.0 or earlier builds.

The future output-inhibited validation is three explicit boot transactions:
GPIO4, GPIO20, then restoration to GPIO4. After each reboot the inspector binds
the exact package, UAPI, route overlay, live device-tree route and pin,
platform-device/driver relationship, canonical endpoint, and disabled
`live_output` state. It never opens or acquires the endpoint.

The qualification archive also contains
`scripts/release_candidate_transaction.py`, an exact-version executor for the
currently installed 1.0.1 predecessor. Because that predecessor is active at
boot, validation first removes only its exactly recognized historical block
and reboots to an inactive baseline. Package replacement then occurs while the
module and endpoint are absent, followed by the GPIO4, GPIO20, and restored
GPIO4 transactions.

Each operation has a separate, digest-bound sidecar plan and immutable operation
identifier. The executor writes and fsyncs its journal before changing boot
configuration, owns only a delimited route block, rejects foreign or duplicate
markers, verifies atomic-write readback, and requires post-reboot reconciliation
against a changed boot ID. Rollback restores only the authenticated bytes saved
by that operation and requires its own reboot reconciliation.
