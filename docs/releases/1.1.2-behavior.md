# Release 1.1.2 behavior

Release 1.1.2 is an unreleased dual-route functional-development candidate.
It preserves ABI v1/v2 and adds the ABI-v3 passive state snapshot, while
retaining both inactive route overlays and the stable
`rp1-gpclk-route-manager-v1` application contract. It does not add an output
operation to the route manager.

The 1.1.1 package cannot enter a live development attempt because its
exact-route compatibility policy rejects both routes even when the immutable
`live_output=1` load-time gate is requested. The earlier 1.1.2 r2 development
source accumulated independent exact functional evidence for GPIO4 and GPIO20 on Raspberry Pi 5
Model B, BCM2712, `aarch64`, kernel `6.18.34+rpt-rpi-2712`, module 1.1.2, the
corresponding route-specific overlay endpoint, RP1 GPCLK0, and the validated
resource topology. Neither route inherits evidence from the other.

The ABI-v3 change creates independent r3 identities for both routes. The r3
entries are fail-closed and do not permit live output until each exact build is
separately requalified. The completed r2 target execution and cleanup results
remain historical evidence for only their exact artifacts and routes; neither
transfers to r3 or to the other route. Hardware-free validation is a separate evidence class, and
no receiver capture or decode was performed. The evidence does not establish
waveform integrity, timing or frequency accuracy, spectral cleanliness, mode
decode, WsprryPi product-path behavior, product eligibility, packaging,
transmitter-system qualification, SDR qualification, RF qualification, or
release qualification.

`live_output` remains disabled by default and read-only after load. Explicitly
requesting it is insufficient unless the exact route, kernel, architecture,
model, module, device-tree, clock, DMA, provider, and resource identities all
pass. ABI-v2 finite TONE remains kernel-bounded; the intended later request of
1,000,000,000 ns is inside the unchanged 1,000,000 through 120,000,000,000 ns
range.

Package installation remains route-neutral and output-inactive. It installs
the module source, inactive overlays, stable route manager, schema,
documentation, and disabled socket units without loading the module, selecting
a route, enabling output, opening the endpoint, acquiring resources, or
rebooting.

The predecessor output-inhibited evidence establishes only route-manager and
cleanup behavior for its exact package. It is not live qualification for the
changed 1.1.2 bytes. No successor 1.1.2 package has been produced by this
development slice. Packaging, consumer binding, target installation, physical
confirmation, WsprryPi policy, waveform-integrity capture, and reviewed plans
remain separate work.

The current canonical UAPI identity is ABI 3 with SHA-256
`f0af5ffda91f4ba82285dc278452eae28b2eeffa635ebd6ee473bf7393a6a54e`.
The ABI-v2 header is retained byte-exact in the 1.1.0 freeze archive. Nothing
in this development state freezes a final UAPI, source identity,
route-overlay identity, compatibility manifest, Debian artifact, inventory,
hash, tag, or consumer identity. Version 1.1.2 remains unreleased; packaging
and immutable artifact freezing are later roadmap work.
