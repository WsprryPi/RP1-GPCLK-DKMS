# Release 1.1.2 security boundary

Version 1.1.2 is an unreleased functional-development identity with independent
GPIO4 r2 and GPIO20 r2 candidates. The canonical UAPI behavior, endpoint,
resource derivation, ownership, generation, cancellation, cleanup, and
route-manager schema remain unchanged. The route-specific overlays use distinct
exact endpoint identities.

Both development entries are deny-by-default and exact. Wrong kernel,
architecture, Pi model, module version, route, overlay endpoint, provider
ancestry, clock, DMA, pinctrl, DMA-tick mapping, exclusive-rate ownership, or
cleanup state rejects the development candidate. Zero active route overlays
provides no endpoint; exactly one valid overlay selects exactly one route; both
overlays present is ambiguous and fails closed. Overlay order cannot choose a
route, and no fallback, substitution, or evidence transfer is permitted.
Hostname is evidence attribution and is not a reusable kernel matching input.

The immutable `live_output` parameter defaults false, is mode 0444, and has no
runtime override. Package installation and the route manager never pass
`live_output=1`. The route manager retains only query, preflight,
apply-and-reboot, rollback, and reconcile; it cannot open the endpoint or run a
carrier plan.

The module reports both r2 entries as `Experimental`, never `Qualified` or
normal product live eligibility. Independently completed GPIO4 and GPIO20
target-functional execution and cleanup evidence does not establish waveform,
spectral, timing, frequency, receiver-capture, decode, WsprryPi product-path,
product-eligibility, packaging, transmitter-system, SDR, RF, or release
qualification. Build and hardware-free validation likewise do not broaden
those claims.

No final UAPI, source, overlay, compatibility, package, inventory, hash, tag,
release, or consumer identity is frozen here. Any packaging, artifact freeze,
consumer integration, qualification, or release requires a later roadmap gate
and separate authorization and review.
