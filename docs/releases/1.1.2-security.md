# Release 1.1.2 security boundary

Version 1.1.2 changes module and package identity because the GPIO4
compatibility result changes. The canonical UAPI, endpoint, overlays, resource
derivation, ownership, generation, cancellation, cleanup, and route-manager
schema remain unchanged.

The positive GPIO4 result is deny-by-default and exact. Wrong kernel,
architecture, Pi model, module version, route, provider ancestry, clock, DMA,
pinctrl, DMA-tick mapping, exclusive-rate ownership, or cleanup state prevents
live eligibility. GPIO20 remains false. Hostname is evidence attribution and is
not a reusable kernel matching input.

The immutable `live_output` parameter defaults false, is mode 0444, and has no
runtime override. Package installation and the route manager never pass
`live_output=1`. The route manager retains only query, preflight,
apply-and-reboot, rollback, and reconcile; it cannot open the endpoint or run a
carrier plan.

Qualification-candidate eligibility is not completed qualification. A later
attempt requires separate authorization, exact target and artifact checks,
physical confirmation, WsprryPi scheduling policy, the minimum supported 2 mA
drive, and an externally reviewed one-second finite-TONE plan. This
hardware-free slice performs none of those actions.
