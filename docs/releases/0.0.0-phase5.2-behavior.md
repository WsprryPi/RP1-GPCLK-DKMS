# 0.0.0-phase5.2 behavioral release notes

This packaging candidate preserves UAPI ABI 1 and the Phase 4 bounded execution
implementation, but deliberately demotes the new module identity to
live-ineligible. It adds a deterministic release-unit generator, independent validator,
machine-readable installation inventory, deny-by-default populated
compatibility manifest, reproducible GPIO4/GPIO20 DTBO artifacts, provenance,
checksums, read-only diagnostics, and operator signing guidance.

Phase 5.3 retains this exact candidate identity and freezes its installation
destinations, ownership, modes, implicit-action prohibitions, and durable
inactive recovery state. The administrator coordinator remains fail-closed:
route activation, module loading, live output, enrollment, boot edits, and
reboot are never implicit.

The release version is `0.0.0-phase5.2` and the expected publication tag is
`v0.0.0-phase5.2`. Its populated GPIO4 and GPIO20 entries are explicit
`Unavailable`, non-live decisions: changing the module version and DTBO
identity invalidates Phase 4's exact candidate identity, firmware identity was
not recorded, and receiver-relative evidence is not calibrated absolute RF
evidence. Live eligibility remains false until later exact lifecycle and
qualification gates add reviewed evidence.

Decision 0010 and the packaged calibrated-review policy allow a future Phase 5
identity to be published as an `Experimental` prerelease after every applicable
packaging, lifecycle, integrity, enrollment, adversarial, and Gate F
prerequisite passes. That policy does not promote this candidate: its current
manifest entries remain `Unavailable` and non-live. Calibrated review must use
the exact frozen packaged candidate, feed a newly reviewed final manifest and
release identity, and trigger a new candidate plus affected Phase 5 lifecycle
reruns if it changes behavior, overlays, UAPI, timing, packaging/generated
bytes, signing, compatibility policy, or lifecycle tooling.

Automatic DKMS rebuild success cannot preserve `Qualified`; a new kernel is at
most `Compatible-unqualified` until an explicit rule and evidence cover it.
Build/signing failure, module/overlay mismatch, cleanup latch, malformed
manifest, and stale Experimental enrollment all fail closed under Decision
0008.

No installation, signing-policy enforcement, key enrollment, target lifecycle,
GPIO, transmission, calibrated measurement, RF, or WsprryPi integration claim
is made by this release-unit slice.
