# RP1-GPCLK-DKMS 1.0.1 planned security notes

Version `1.0.1` remains deny-by-default and live-ineligible without an exact
positive compatibility entry. Live submission requires both the immutable
load-time `live_output`
gate and an exact positive compatibility entry for the complete identity and
selected route; otherwise it fails with `EACCES`. GPIO4 approval never implies
GPIO20 approval, or vice versa. `QUERY` may report implemented capabilities
without reporting `LIVE_ELIGIBLE`.

The sole positive candidate entry requires exact equality for route, kernel
release, architecture, Pi 5 Model B identity, and successful acquisition of
the already validated clock, DMA, pinctrl, and mapped tick resources. There
are no prefixes, wildcards, alternate kernels, alternate architectures, or
GPIO20 transfer. The read-only `live_output` module parameter remains an
independent mandatory gate.

The endpoint bootstrap accepts one enabled OF
node, reuses a correctly bound kernel-created platform device, or creates only
that node beneath its nearest instantiated platform ancestor while retaining
the endpoint's validated RP1 firmware ancestry. It never populates the RP1 bus
generally and never unregisters a kernel-created device.

The module observes platform-device removal, holds a temporary reference while
publishing ownership, clears only an owned endpoint's populated flag after
unregister, and unwinds initialization in reverse order. Missing,
duplicate, disabled, unbound, removed, or ambiguous endpoints reject module
initialization.

These controls have hardware-free evidence only. They do not establish target,
GPIO, timing, transmission, or RF qualification.
