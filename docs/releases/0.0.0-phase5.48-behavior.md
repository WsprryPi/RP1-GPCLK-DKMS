# 0.0.0-phase5.48 behavior

Phase 5.48 binds every Gate D attempt's service pre-state to the canonical
live-target snapshot. An inactive service must remain inactive. An active
service must be stopped only through its sealed action and restored to its
exact pre-attempt state during terminal recovery.

Independent validation rejects missing or duplicate service coverage, stale
snapshot identity, inconsistent state/action pairs, per-attempt state leakage,
and disagreement among the target plan, attempt bundle, and execution
envelope. The module runtime and UAPI are unchanged.

This candidate is not lifecycle-ready until a new deterministic archive,
representative build, complete Gate D control set, and explicit authorization
are independently established.
